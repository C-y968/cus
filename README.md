# 客序 · 客户关系工作台

为大客户销售准备的单人客户档案工具。同一个网页适配电脑和手机：手机采集拜访录音，电脑按 **公司 → 业务部门 → 客户** 查看并持续维护档案。

## 现在如何使用

1. 双击本目录的 **启动客序.command**（Mac），或在目录中运行 `npm run start:background`。后台启动成功后可关闭终端窗口。
2. 电脑打开 `http://127.0.0.1:4380`，首次设置至少 10 位工作台密码。
3. 点击“新建客户”，填公司、部门、客户姓名。也可以先点“体验虚构示例”，示例与真实模型调用无关，可删除。
4. 进入“设置”，分别配置语音转写、内容提炼模型的 Base URL、模型名称、API Key，保存并测试。
5. 手机打开同一工作台的 `/capture` 入口，选择客户后直接录音、上传系统录音，或粘贴会后文字。
6. 点击“保存并更新客户档案”。后台自动处理，录音和文字均留在该客户的拜访时间线。

没有填写模型配置时也可以创建客户、保存录音和文字。记录会显示“待配置转写”或“待配置提炼”。配置完成后在设置页点击“保存并处理等待中的记录”，或打开单次记录点击“重试处理”。

## 已实现

- 电脑工作台、公司/部门目录、客户搜索、新建与编辑、组织重命名、客户归属调整。
- 直接录音、暂停/继续、停止试听、下载录音；上传 MP3/M4A/WAV/WEBM/OGG/FLAC/AAC/AMR 等，单文件最多 200 MB。
- 手机入口、二维码、添加到主屏幕的 Web App 清单。当前不提供离线应用缓存。
- 浏览器本机录音草稿备份和刷新恢复；断开页面前已保存的片段可尝试恢复。意外中断的文件需先试听，不能保证来电/系统终止后音频完整。
- 语音自动转写；安装 FFmpeg 时统一为 16 kHz、单声道、48 kbps MP3，按 10 分钟分段，顺序调用转写服务。
- 文字超过 12,000 字按段提炼，所有段成功后一次性提交客户档案，避免中途部分写入。
- 三维档案：业务方向 / 个人诉求 / 个人客情。事实保留连续原话、日期与拜访来源。
- 重复事实追加来源；同一字段出现不同值进入待核对；可采用新信息、并存或忽略。旧值保留历史。
- 已归档事实可人工修订；旧值留档，新值标记“人工修订”，原话不被改写。
- 跟进事项自动提取与手动添加、完成/恢复状态；不自动向客户发送消息。
- 处理队列、服务重启中断提示、手动重试、上传请求去重。
- 原始录音下载、单客户 Markdown 档案导出、全部客户 JSON 导出。
- 单人密码登录、服务端会话、跨站写请求校验、登录限速、密钥加密保存、受登录保护的录音访问。

## 手机连接

### 同一 Wi-Fi：立即使用录音上传

Mac 启动文件默认开启局域网监听；命令行可运行：

```sh
npm run start:background
```

手机与电脑连接同一网络，在“设置 → 本机局域网地址参考”查看地址，把它填入“手机可访问的工作台地址”并保存。扫码或浏览器打开地址后，用同一个密码登录。电脑需要保持运行。

局域网 HTTP 可以上传手机“语音备忘录 / 录音机”生成的文件。浏览器直接访问麦克风通常要求 **HTTPS**，本机 `localhost` 是例外。因此手机访问 HTTP 局域网地址时，界面会引导使用录音上传。

### 跨网络 / 手机直接网页录音

需要把服务部署到可访问的服务器，并配置 HTTPS 域名。仓库包含 `Dockerfile`、`compose.yaml` 和 `Caddyfile.example` 作为部署模板，但本次没有创建公网域名、购买服务器或发布到互联网。

启动后手机可从浏览器菜单选择“添加到主屏幕”。录音期间保持页面在前台；不要依赖网页在锁屏、切换应用、来电后持续录音。长时间拜访优先使用系统录音机，结束后上传。

## 模型配置约定

两个模型使用 **OpenAI 兼容的 HTTP 协议**，可使用不同服务商；不是所有厂商的原生接口都兼容。

| 配置项       | 语音转写                                                    | 内容提炼                                     |
| ------------ | ----------------------------------------------------------- | -------------------------------------------- |
| Base URL     | 如 `https://api.example.com/v1`                             | 如 `https://api.example.com/v1`              |
| 自动追加路径 | `/audio/transcriptions`                                     | `/chat/completions`                          |
| 请求         | multipart：file、model、response_format=json、可选 language | messages、model、response_format=json_object |
| 返回         | `{ "text": "完整文字稿" }`                                  | `choices[0].message.content` 内的 JSON 对象  |
| 密钥         | Authorization: Bearer                                       | Authorization: Bearer                        |

- Base URL 填接口根地址，不要重复填写末尾路径。只接受 HTTPS，明确的本机服务允许 HTTP。
- 模型名称以服务商控制台实际可用的名称为准。默认转写名称 `whisper-1` 只是可编辑预填值；提炼模型不预设。
- 当前要求填写模型名称与密钥；使用无鉴权的本机兼容服务时可填服务端忽略的占位密钥。
- 密钥留空表示保留，勾选“清除已保存密钥”后保存才删除。
- “保存并测试”发出真实请求，可能产生少量服务商费用；转写测试发送短静音 WAV，提炼测试发送短文字。测试不含客户资料。
- 正式处理会发送相应录音或文字到你指定的服务商。失败不会无限自动重试，避免重复计费。
- 若服务商不支持 `response_format=json_object`，请选兼容接口或适配 `server/ai.js`。
- 无 FFmpeg 时，可直接转写小于 24 MiB 的原始文件；更大文件保留并提示安装 FFmpeg。工具自动分段时，1 小时录音转码后约 21.6 MB，产生约 6 次转写请求；模型费用按服务商计算。
- 文字稿上限 200,000 字。超出上限的超长录音转写会提示拆分；单次文件上传上限 200 MB。

## 提炼与归档规则

1. 每条记录必须人工选择客户，避免自动猜测同名客户和参会者归属。
2. 模型只提取录音/文字中有依据的信息。销售的个人偏好不能归给客户；不推断敏感身份、健康、政治或心理特征。
3. 系统检查原话是原稿的连续子串；没有可核验原话的候选条目不写档。
4. 自动写入模式下，无冲突且模型自报置信度不低于 0.85 的新事实直接归档；不明确与冲突条目进入待核对。此数字是工作流阈值，不代表实测准确率。
5. 重复判断依赖维度、规范化字段名和内容；同义表述并非完美语义去重。提示词要求沿用既有字段名，人工仍可修订。
6. “替换”把同字段旧值存为历史；“并存”保留两个当前值；“忽略”将候选条目标记为已忽略。
7. 行动日期仅在原稿明确出现 `YYYY-MM-DD` 日期时自动填写，不猜测“明天”“下周”。日期待定的事项可查看原话后手动添加具体安排。
8. 模型摘要与候选信息仍可能出错。重要信息应点击来源核对，尤其是多人录音和客户身份不清的记录。

## 数据、权限和备份

这是 **单人工作台**：同一密码登录的设备能访问全部客户。不是有员工隔离权限的企业 CRM。

- 默认数据目录：`data/`，包含 `compass.sqlite`、SQLite WAL 文件、`audio/` 和 `.encryption-key`。
- 模型密钥用 AES-256-GCM 加密保存，不发回浏览器、不包含在资料导出中。加密主密钥保存在同一台机器的 `.encryption-key`，备份时必须一起保留。
- 客户数据库与音频本身不是端到端加密。操作系统账号、磁盘加密、服务器访问权限和模型服务商数据政策需要适合实际使用环境。
- 客户数据不写进浏览器 localStorage。录音草稿存在当前浏览器 IndexedDB，提交成功或移除草稿后删除；不要在共用设备上留下草稿。
- 删除拜访会移除原始录音、该次产生的行动，以及仅由该次拜访支撑的事实。多次拜访共同支撑的事实保留其他来源。
- 删除客户会删除其全部拜访、音频、事实和事项。界面会要求确认。
- JSON 导出不含音频、登录密码和模型密钥，属于资料导出，不能替代完整备份。

**完整备份：**先停止服务（双击“停止客序.command”或运行 `npm run stop`；使用前台 `npm start` 的终端按 `Ctrl+C`），运行 `npm run backup`。会在 `backups/` 生成带日期的完整数据备份，含密钥和音频。备份文件同样属于私密资料。

**恢复：**停止服务，保留现有 `data/` 副本，把某份完整备份目录内的文件整体复制到 `data/`，再启动。更换 `DATA_DIR` 时恢复到对应目录。不要混用不同备份的数据库和 `.encryption-key`。

**忘记密码：**停止服务后，在本项目运行 `npm run reset-password`，按终端确认提示重置登录设置。客户资料不删除，全部旧会话失效；重启后在运行服务器的电脑上重新设置密码。

## 本地开发与启动

要求 Node.js 24，推荐安装 FFmpeg。当前交付已安装依赖和生成 `dist/`。

```sh
npm ci
npm run build
npm start
```

后台管理：

```sh
npm run start:background  # 独立后台运行，默认允许局域网访问
npm run status            # 核验当前实例及访问地址
npm run stop              # 核验进程身份后停止，保留客户数据
```

Mac 可直接双击“启动客序.command”和“停止客序.command”。重复启动会复用已有实例；若端口被其他程序占用，不会结束该程序。还有拜访正在处理时，停止操作会提示等待。日志与进程记录位于 `.runtime/`，不包含在完整数据备份中。

后台运行仍需要电脑开机、保持唤醒。电脑重启后需再次启动；未设置开机自启或周期监控。`npm start` 和 `npm run start:lan` 保留原有前台运行方式。

可选环境变量：

| 变量          | 默认      | 用途                       |
| ------------- | --------- | -------------------------- |
| PORT          | 4380      | 服务端口                   |
| HOST          | 127.0.0.1 | 用 0.0.0.0 接受局域网请求  |
| DATA_DIR      | ./data    | 数据持久化目录             |
| PUBLIC_URL    | 空        | 未保存设置时的手机访问地址 |
| FFMPEG_PATH   | ffmpeg    | FFmpeg 可执行程序路径      |
| COOKIE_SECURE | 未启用    | HTTPS 部署时设为 1         |
| TRUST_PROXY   | 未启用    | 在受控单层反向代理后设为 1 |

开发：`npm run dev`，前端 `http://127.0.0.1:4381`，后端 `http://127.0.0.1:4380`。
